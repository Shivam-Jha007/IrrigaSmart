# 03_Data_Models.md

# IrrigaSmart

## Data Model Specification

Version: 1.0

Status: Active

---

# Purpose

This document defines the core data entities used throughout IrrigaSmart.

These entities represent the information exchanged between the frontend, backend, decision engine, storage layer, and future services.

This document defines **what data exists**, not **how it is stored** or **how it is processed**.

---

# Design Principles

The data model should be:

- Simple
- Consistent
- Extensible
- Strongly Typed
- Independent of UI
- Independent of Database

Every module in the application should communicate using these shared models.

---

# Core Entities

The MVP consists of the following primary entities:

- Farmer
- Farm
- Crop
- Soil
- WeatherData
- Recommendation
- IrrigationSchedule
- HistoryRecord
- Settings

---

# Farmer

Represents the primary user of the application.

Fields

- Farmer ID
- Name
- Preferred Language
- Phone Number (Optional)
- Created Date

A farmer may own one or more farms.

---

# Farm

Represents a physical agricultural field.

Fields

- Farm ID
- Farmer ID
- Farm Name
- Location
- Area
- Area Unit
- Soil Type
- Irrigation Method
- Primary Crop

Each farm belongs to exactly one farmer.

---

# Crop

Represents the crop currently cultivated.

Fields

- Crop ID
- Crop Name
- Growth Stage
- Typical Water Requirement
- Crop Category

The detailed agronomic values are maintained in the agricultural knowledge base.

---

# Soil

Represents the dominant soil characteristics of a farm.

Fields

- Soil ID
- Soil Name
- Water Retention Category
- Drainage Category

Future versions may include additional physical properties.

---

# WeatherData

Represents the weather information used during recommendation generation.

Fields

- Temperature
- Humidity
- Rainfall Forecast
- Wind Speed
- Cloud Cover
- Observation Time
- Data Source

Weather data should always include the timestamp of retrieval.

---

# Recommendation

Represents the output generated by the Decision Engine.

Fields

- Recommendation ID
- Farm ID
- Recommendation Status
- Recommended Time
- Estimated Water Amount
- Explanation
- Confidence Level
- Generated Time

The Recommendation entity is the primary object displayed to the user.

---

# Irrigation Schedule

> **MVP status: Future / not implemented in MVP.**
> The MVP generates one on-demand recommendation per farm per day and does not
> produce or persist schedules. This entity is defined here for forward
> compatibility only. See `11_Decision_Logic.md` §10 (Assumptions).

Represents planned irrigation activities.

Fields

- Schedule ID
- Farm ID
- Date
- Time
- Planned Water Amount
- Status

Schedules may be automatically generated or manually adjusted in future versions.

---

# History Record

Stores previous recommendations.

Fields

- History ID
- Farm ID
- Recommendation ID
- Generated Date
- Actual Irrigation Performed (Future)

History enables users to review previous irrigation advice.

---

# Settings

Represents user preferences.

Fields

- Preferred Language
- Notification Preference
- Offline Sync Preference
- Units (Metric)

Settings should remain independent from business logic.

# Ownership Rules

A Recommendation belongs to one Farm.

A Farm belongs to one Farmer.

Weather data is associated with a Farm location.

History records reference previous Recommendations.

---

# Future Extensions

The model should support future entities such as:

- Sensor Data
- Soil Moisture
- Water Quality
- Satellite Observation
- Disease Detection
- Yield Prediction

These should extend the model without breaking existing entities.

---

# Out of Scope

This document does not define:

- Database schema
- SQL tables
- API payloads
- TypeScript interfaces
- Validation rules

These are defined in separate documents.

---

# Success Criteria

The data model is considered successful if:

- Every module uses the same entities.
- New features can reuse existing models.
- Business logic remains independent of storage.
- Future data sources can be integrated without redesign.
